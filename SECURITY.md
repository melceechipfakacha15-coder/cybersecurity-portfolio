# Repository Safety

This portfolio is public. Treat every committed file as information that an employer, recruiter, or stranger can view.

## Never commit

- Passwords, API keys, tokens, cookies, private keys, recovery codes, or connection strings
- Personal email headers, addresses, phone numbers, account names, or other identifying information
- Real employer, customer, clinic, patient, school, or family data
- Complete production logs or packet captures
- Malware binaries, weaponized scripts, or instructions intended to harm systems
- Screenshots that expose private browser tabs, file paths, Wi-Fi names, device names, public IP addresses, or notifications

## Before publishing evidence

1. Work only in an authorized lab or simulation.
2. Keep original evidence outside this repository.
3. Replace identifying values with clear labels such as `USER-01`, `HOST-01`, and `192.0.2.10`.
4. Crop screenshots to the evidence needed for the explanation.
5. Review the staged changes before every commit.
6. If a secret is committed, revoke it immediately; deleting the file alone is not enough.

## Scope

The projects here demonstrate defensive analysis, troubleshooting, documentation, and incident-response thinking. They do not authorize testing against systems I do not own or have explicit permission to assess.
